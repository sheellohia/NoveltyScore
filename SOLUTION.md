## 1. Problem & content shape

The system scores the **novelty** of structured user-generated submissions. Each topic has a fixed piece of content (at most 100 words) and a corpus of existing submissions; a new submission is scored on how much it adds beyond both, without rewarding off-topic or duplicated text, and its sentences are labelled as new vs. already said. Nothing in the method depends on what the content is about; §3 lists illustrative mappings onto concrete domains.

| Field | Shape | Enforced |
|---|---|---|
| header | one line (soft cap 120 chars) | UI hint |
| content | paragraph, ≤ 100 words | UI hard cap + API 400 |
| takeaway | one line, ≤ 120 characters | UI hard cap + API 400 |

Corpus used for every experiment:

| topic_id | corpus items | held-out cases |
|---|---|---|
| ai_tutors | 50 | 4 |
| ev_green | 50 | 4 |
| four_day_week | 50 | 4 |
| remote_work | 50 | 4 |
| teen_social_media | 50 | 4 |

Fixtures per topic: 5 planted near-duplicates (each paired with the original it copies), 5 planted generic items, and 4 held-out cases: **T1** novel & relevant (expect high), **T2** novel but irrelevant (expect very low), **T3** near-duplicate (expect low), **T4** generic but relevant (expect low-medium).

## 2. Engineering design

```
  React/Vite UI ──POST /api/score──▶ FastAPI main.py ──▶ scoring.novelty.score()
                                                            │
        ┌───────────────────────────────┬──────────────────┼────────────────────┐
        ▼                               ▼                  ▼                    ▼
  corpus_cache (startup, per topic)  pipeline.py        baseline.py           judge.py (Gemini)
  embed corpus fields                measure():         TF-IDF nearest-       benchmark only,
  LOO: each item vs other N-1  ───▶    relevance, kNN,  neighbor novelty      never in system_score;
  → reference distributions            recombination    → baseline_score      verdicts cached in
  → relevance_floor (on/off-topic)     gate relevance                         results/judge_cache.json
  → dedup_threshold (p95)          finalize():                                → llm_score
  → LOO raw-score distribution ─┐     rank-fuse → asymmetric gate → raw
                                └──▶ system_score = percentile of raw in the LOO distribution
```

| Component | File | Responsibility |
|---|---|---|
| Data loader | `backend/data_loader.py` | Glob `data/corpus/*.json`, key by internal `topic_id`; fixtures from `data/fixtures/` |
| Embeddings | `backend/scoring/embed.py` | Local ONNX embeddings (`snowflake/snowflake-arctic-embed-m`), unit-normalized, memoized |
| Pipeline | `backend/scoring/pipeline.py` | The single scoring path used for live submissions and LOO corpus items |
| Recombination | `backend/scoring/recombination.py` | Per-field top-5 neighbor sets, 1 − mean pairwise Jaccard |
| Calibration | `backend/scoring/corpus_cache.py` | LOO distributions, derived thresholds, startup fixture validation |
| Baseline | `backend/scoring/baseline.py` | TF-IDF nearest-neighbor novelty (the reference to beat) |
| Surfacing | `backend/scoring/surfacing.py` | Sentence-level new vs. already-said labels, closest submission id, net-new ratio |
| Judge | `backend/scoring/judge.py` + `prompts/` | Gemini rubric judge; live and listwise-LOO protocols; persistent cache |
| Experiments | `experiments/run_experiments.py` | Sweep, LOTO selection, criteria, determinism, judge variance |

**Data flow for one submission.** Header, content and takeaway are embedded separately. Against the topic corpus the pipeline measures relevance (cos(content, fixed content)), nearest-neighbor novelty (k=1, base field weights {'header': 0.2, 'content': 0.6, 'takeaway': 0.2}, aggregation `info_weighted`) and recombination novelty. The two novelty signals are rank-fused with weights {'knn': 0.7058823529411765, 'recombination': 0.29411764705882354}, multiplied by the asymmetric relevance gate (gate signal: `centroid`; floor method: `offtopic`; temperature mode: `adaptive`, target gate 0.95 at the on-topic p5), and the result is reported as its percentile within the topic's leave-one-out distribution. Because corpus items go through exactly the same code (excluding themselves), a score of 0.8 means "more novel than 80% of this topic's own corpus".

## 3. Design rationale

Each choice below lists its research basis, the alternative that was rejected, and the recorded ablation delta. Spearman is the mean per-topic Spearman correlation with the cached judge over all corpus items (leave-one-out); "pass-rate" is the planted-case pass-rate (T1>T4>T3>T2, T2<0.2, T1>0.6).

### Relevance gate: asymmetric (MCNS) vs harmonic

*Basis.* Minimal Criteria Novelty Search (Lehman & Stanley, GECCO 2010): a candidate must first satisfy a minimal criterion (here: be on-topic), after which only novelty matters. *Rejected alternative:* a harmonic mean of novelty and relevance, which is symmetric, so in principle very high novelty can compensate for being off-topic. Whether the data support the choice is stated below the table.

Asymmetric minus harmonic, same embedding and combine:

| embedding / combine | Δ Spearman | Δ T2 max (lower is better) | Δ pass-rate |
|---|---|---|---|
| all-MiniLM-L6-v2 / linear | +0.012 | +0.000 | +0.0 |
| all-MiniLM-L6-v2 / rankfusion | -0.112 | +0.300 | +0.2 |
| all-mpnet-base-v2 / linear | +0.007 | +0.020 | -0.4 |
| all-mpnet-base-v2 / rankfusion | -0.125 | +0.000 | +0.0 |
| snowflake-arctic-embed-m / linear | +0.250 | +0.000 | +0.4 |
| snowflake-arctic-embed-m / rankfusion | +0.070 | +0.000 | +0.6 |

Where the asymmetric gate helped (per embedding): all-MiniLM-L6-v2: higher Spearman in 1/2, lower max T2 in 0/2; all-mpnet-base-v2: higher Spearman in 1/2, lower max T2 in 0/2; snowflake-arctic-embed-m: higher Spearman in 2/2, lower max T2 in 0/2. **Trade-off:** it gave higher judge correlation in 4/6 pairs but lower max T2 in only 0/6; the alternative rejected the off-topic case better. The choice was made on judge correlation, and C1 (§4) reflects its cost.

Ladder: adding the gate to ungated kNN (L1 +embeddings (kNN, ungated, raw) → L2 +gate (asymmetric, fixed floor)) raised Spearman by +0.089 and changed max T2 from 0.423 to 0.109.

<sub>source: `results/summary.csv`</sub>

### Calibration: leave-one-out percentiles vs raw scores

*Basis.* The LOO percentile is a jackknife conformal p-value: the corpus item scored against the other N−1 is exchangeable with a new submission scored against all N (Vovk et al., 2005; Bates et al., "Testing for outliers with conformal p-values", Ann. Statist. 2023). It gives every topic the same 0–1 meaning and derives thresholds from the topic's own data. *Rejected alternative:* raw similarity scores with fixed constant thresholds.

| metric | L2 +gate (asymmetric, fixed floor) | L3 +calibration (LOO percentiles, p10 floor) | Δ |
|---|---|---|---|
| Spearman (mean per topic) | 0.529 | 0.545 | +0.016 |
| Spearman (pooled) | 0.540 | 0.539 | -0.001 |
| pass-rate | 0.000 | 0.000 | +0.000 |
| redundancy in bottom quartile | 0.760 | 0.740 | -0.020 |
| T1 mean | 0.176 | 0.764 | +0.588 |
| T2 max | 0.109 | 0.360 | +0.251 |

Within one topic a percentile transform is monotone, so per-topic Spearman changes only through the derived relevance floor; the pooled Spearman and the absolute-threshold checks (T1>0.6, T2<0.2) are where calibration is expected to matter.

<sub>source: `results/summary.csv`</sub>

### Recombination novelty (Uzzi-style)

*Basis.* Uzzi, Mukherjee, Stringer & Jones, "Atypical combinations and scientific impact", Science 2013: work that combines conventional material in atypical pairings is disproportionately high-impact. Here: if a submission's header, content and takeaway land near *different* corpus items, it bridges regions that do not normally co-occur. *Rejected alternative:* nearest-neighbor distance only.

| step | Δ Spearman | Δ pass-rate | Δ redundancy | Δ T2 max |
|---|---|---|---|---|
| L3 +calibration (LOO percentiles, p10 floor) → L4 +recombination (pre-fix gate) | +0.017 | +0.4 | +0.06 | -0.100 |

<sub>source: `results/summary.csv`</sub>

### Rank fusion vs linear blend

*Basis.* Score fusion over ranks rather than raw values (Borda-style; cf. reciprocal rank fusion, Cormack, Clarke & Büttcher, SIGIR 2009): signals with different scales and spreads cannot dominate by accident, so the blend weights mean what they say. Implemented as a weighted mean of within-topic LOO percentiles. *Rejected alternative:* linear blend of raw signal values. Whether the data support the choice is stated below the table.

| embedding / gate | Δ Spearman (rankfusion − linear) | Δ T2 max (lower is better) | Δ pass-rate |
|---|---|---|---|
| all-MiniLM-L6-v2 / harmonic | +0.061 | +0.020 | -0.2 |
| all-MiniLM-L6-v2 / asymmetric | -0.063 | +0.320 | +0.0 |
| all-mpnet-base-v2 / harmonic | +0.103 | +0.000 | -0.4 |
| all-mpnet-base-v2 / asymmetric | -0.029 | -0.020 | +0.0 |
| snowflake-arctic-embed-m / harmonic | +0.212 | +0.000 | +0.0 |
| snowflake-arctic-embed-m / asymmetric | +0.032 | +0.000 | +0.2 |

Where the rank fusion helped (per embedding): all-MiniLM-L6-v2: higher Spearman in 1/2, lower max T2 in 0/2; all-mpnet-base-v2: higher Spearman in 1/2, lower max T2 in 1/2; snowflake-arctic-embed-m: higher Spearman in 2/2, lower max T2 in 0/2. **Trade-off:** it gave higher judge correlation in 4/6 pairs but lower max T2 in only 1/6; the alternative rejected the off-topic case better. The choice was made on judge correlation, and C1 (§4) reflects its cost.

### Embedding model

*Basis.* Sentence-embedding bi-encoders (Reimers & Gurevych, 2019): all-MiniLM-L6-v2 (MiniLM distillation, Wang et al., 2020), all-mpnet-base-v2 (MPNet, Song et al., 2020), and snowflake-arctic-embed-m (Merrick et al., 2024), the deployed model. The probe rows score ungated, uncalibrated kNN novelty only, so they compare the embeddings without the gate hyperparameters (which were tuned on the deployed model).

| probe | Spearman | redundancy in bottom quartile | planted copy's NN = its original | percentile of that NN similarity |
|---|---|---|---|---|
| P all-MiniLM-L6-v2 kNN only | -0.014 | 0.22 | 80% | 0.57 |
| P all-mpnet-base-v2 kNN only | 0.045 | 0.26 | 76% | 0.58 |
| P snowflake-arctic-embed-m kNN only | 0.462 | 0.64 | 80% | 0.67 |

The last two columns separate *finding* the copied original from *recognizing it as unusually close*: a model can retrieve the right nearest neighbor while rating that pair only slightly more similar than ordinary same-topic neighbors (percentile near 0.5), in which case nearest-neighbor novelty cannot single out the copy. This accounts for the redundancy column; it does not by itself explain the Spearman column, which is measured over all corpus items, not only the planted ones.

### Field aggregation and net-new blending (ablation-decided)

Two pre-registered, toggleable changes to how novelty is aggregated, each judged by one rule fixed in code before the run: *KEEP iff mean LOO Spearman vs judge > base AND planted-case pass-rate >= base*. Hand-written inputs played no part in the decision.

- **Information-adaptive field weights** (`FIELD_AGGREGATION=info_weighted`): field weight ∝ base weight × log(1 + non-generic tokens), renormalized; a token is generic if it is a stopword or appears in ≥ 0.2 of the topic's corpus submissions. A short or generic header can no longer dilute a substantive content field. *Basis:* information content as inverse document frequency (Spärck Jones, 1972). *Alternative:* fixed 0.2/0.6/0.2 field weights.
- **Sentence-level net-new blend** (`NET_NEW_BLEND`): mix `surfacing.net_new_ratio` into the kNN novelty signal with γ = 0.6, either on raw values (`raw`) or on within-topic percentiles (`rank`, the scale-free variant: raw kNN novelty and net-new live on different scales). *Basis:* TREC-style new-information signal.

| variant | Spearman | Δ vs base | pass-rate | Δ | topics improved | Spearman vs judge run 1 (base → variant) | run 2 | decision |
|---|---|---|---|---|---|---|---|---|
| AGG base (fixed_mean, no net-new) | 0.459 | — | 0.6 | — | — | — | — | base |
| AGG A info-weighted fields | 0.477 | +0.018 | 0.6 | +0.0 | 4/5 | 0.439 → 0.448 | 0.475 → 0.499 | **KEEP** |
| AGG B-raw net-new blend (raw) | 0.304 | -0.154 | 0.4 | -0.2 | 1/5 | 0.439 → 0.328 | 0.475 → 0.317 | **REVERT** |
| AGG B-rank net-new blend (rank) | 0.441 | -0.017 | 0.6 | +0.0 | 2/5 | 0.439 → 0.433 | 0.475 → 0.461 | **REVERT** |
| AGG A+B-raw | 0.315 | -0.144 | 0.4 | -0.2 | 1/5 | 0.439 → 0.337 | 0.475 → 0.325 | **REVERT** |
| AGG A+B-rank | 0.456 | -0.003 | 0.6 | +0.0 | 3/5 | 0.439 → 0.437 | 0.475 → 0.476 | **REVERT** |

Kept: AGG A info-weighted fields. Leave-one-topic-out selection over these candidates chose AGG A info-weighted fields in every fold (1 distinct selection(s)); mean per-fold in-sample vs held-out gap 0.026. The judge-run columns are a robustness check against the judge's own run-to-run noise (runs 1–2 shuffle item order) and were not used for the decision.

Both net-new blend forms lowered judge correlation, so sentence-level net-new stays an explanatory output (surfacing) rather than a score input. A plausible reading, not tested here: sentence redundancy reacts to rewording, while the judge scores ideas.

### Redundancy-aware surfacing (sentence-level new information)

*Basis.* The TREC Novelty Track (Harman, 2002; Soboroff & Harman, 2003) defines the task of finding, sentence by sentence, material that is both relevant and not already seen; Allan, Wade & Bolivar (SIGIR 2003) showed sentence-level redundancy is dominated by similarity to the closest previously seen sentence. Here each content sentence gets redundancy = max cosine to any sentence of any existing submission (1 − that is its novelty contribution). Thresholds are self-calibrated like the rest of the system: every corpus sentence is scored against the sentences of the *other* submissions, and a sentence is **redundant** at or above the p75 of that distribution, **novel** at or below the p50, **partial** in between. `net_new_ratio` is the word-weighted share of novel + partial sentences. It is reported and explained, and does not change `system_score`. Surfacing measures *newness* only; the *relevant* half of the TREC task is handled at submission level by the relevance gate and the `low_relevance` flag (the UI marks surfacing of a low-relevance submission as not relevant). *Rejected alternatives:* document-level novelty only (cannot say *which* part is new); fixed absolute cosine thresholds (not comparable across embeddings); reusing the scoring embedding for sentences (see the model sweep).

| all-MiniLM-L6-v2 | 0.646 | 0.62 | 0.78 | 26/34 | 0.61 | 0.36 |
| all-mpnet-base-v2 | 0.750 | 0.51 | 0.77 | 36/45 | 0.66 | 0.26 |

Deployed sentence model: `sentence-transformers/all-mpnet-base-v2`. Mean net-new of the held-out cases: T1 0.66, T2 1.00, T3 0.26, T4 0.60.

### Illustrative application mappings (examples only)

The method only assumes: a fixed reference text per topic, a corpus of earlier submissions, and submissions with a short headline, a body of at most 100 words and a one-line summary. The mappings below are *illustrative*; none of them is built into the code, prompts or metrics.

| domain (illustrative) | fixed content | corpus | header | content | takeaway |
|---|---|---|---|---|---|
| Product reviews | product description | earlier reviews of that product | review title | review body | one-line verdict |
| Article comments | article excerpt | earlier comments | comment headline / first line | comment body | one-line summary |
| Forum threads | original question | earlier replies | reply subject | reply body | tl;dr |

In each case redundancy-aware surfacing is the "skip what's already been said, surface what's new" view: a reader sees which sentences add information beyond the existing submissions. Fields a domain has that the system does not read (for example a star rating) are simply not used. The system measures relevance, novelty and redundancy only; it does **not** assess sentiment, quality, factual accuracy, helpfulness, authenticity or fraud.

### Bug fixes & calibration

**Bug 1: the relevance floor ranked on-topic items instead of rejecting off-topic ones.** The floor was the 10th percentile of the topic's own relevance distribution. Every corpus item is on-topic, so by construction a tenth of genuinely on-topic items sat below the floor, and the soft gate cut their novelty even though nothing was wrong with them. On a homogeneous-relevance corpus a within-topic percentile cannot tell "less relevant" from "irrelevant". The gate's job (a minimal criterion) is the second: separate on-topic from off-topic, then let novelty alone rank.

| topic | floor before | floor after | floor bound by | on-topic gate < 0.9 before | after | T2 before | T2 after | other topics' mean gate (after) |
|---|---|---|---|---|---|---|---|---|
| ai_tutors | 0.610 | 0.742 | on-topic cap | 34% | 4% | 0.26 | 0.00 | 0.39 |
| ev_green | 0.667 | 0.730 | on-topic cap | 52% | 6% | 0.02 | 0.00 | 0.16 |
| four_day_week | 0.618 | 0.758 | on-topic cap | 58% | 2% | 0.00 | 0.00 | 0.31 |
| remote_work | 0.686 | 0.759 | on-topic cap | 48% | 2% | 0.00 | 0.00 | 0.32 |
| teen_social_media | 0.652 | 0.764 | on-topic cap | 38% | 2% | 0.00 | 0.00 | 0.25 |

The four-day-week submission used in UI testing: gate 0.918 → 1.000, final score 0.48 → 0.34 (the final moves because every corpus item now passes the gate too, so the reference distribution shifts up).

**Finding: the other topics are not off-topic enough to set the floor.** The floor is min(off-topic mean + 2.0σ, on-topic p5 − 0.02), where "off-topic" is the other topics' corpora. The on-topic cap was the binding term in 5/5 topics: the five topics share vocabulary, so other-topic items overlap this topic's relevance distribution (see the last column).

**Why the gate signal and temperature changed.** Variants compared (all on the deployed embedding):

| variant | note | Spearman | pass-rate | T2 max | redundancy | on-topic gate ≥ 0.9 |
|---|---|---|---|---|---|---|
| L4 +recombination (pre-fix gate) | pre-fix | 0.562 | 0.4 | 0.26 | 0.80 | 54% |
| V1 brief literal: fixed-content signal, off-topic floor, temp 0.05 |  | 0.515 | 0.4 | 0.58 | 0.76 | 55% |
| V2 fixed-content signal, off-topic floor, adaptive temp |  | 0.467 | 0.4 | 0.92 | 0.70 | 95% |
| V3 centroid signal, off-topic floor, temp 0.05 |  | 0.490 | 0.4 | 0.26 | 0.70 | 27% |
| V5 no gate (novelty only) |  | 0.453 | 0.0 | 1.00 | 0.66 | 97% |
| L5 +on/off-topic gate | adopted | 0.459 | 0.6 | 0.00 | 0.66 | 97% |

Variants meeting both goals (max T2 < 0.2 and ≥ 90% of on-topic items at gate ≥ 0.9): L5 +on/off-topic gate. Cosine to the 100-word fixed content could not separate an off-topic text that shares vocabulary with it; cosine to the topic corpus centroid could. A wider fixed temperature leaves on-topic items near the floor partly gated; the adaptive temperature places the on-topic p5 at gate 0.95 in every topic.

**Judge-correlation delta (same cached judge throughout).**

| system | Spearman vs judge | source |
|---|---|---|
| before: with category, pre-fix gate | 0.582 | `results/before_fix/experiments.json` |
| category removed, pre-fix gate | 0.562 | `summary.csv` → L4 +recombination (pre-fix gate) |
| category removed, fixed gate (current) | 0.459 | `summary.csv` → L5 +on/off-topic gate |
| no gate at all (novelty only) | 0.453 | `summary.csv` → V5 |

The gate fix lowered judge correlation by 0.103 (0.562 → 0.459). The reason is measurable: the judge itself marks weakly-relevant on-topic items down (within-topic Spearman between absolute relevance and judge score: 0.263; items the pre-fix gate suppressed averaged judge 0.21 vs 0.53 for the rest). The old gate's double penalty therefore happened to agree with the judge. The fix keeps a single penalty for redundancy (novelty) and a pass/fail for relevance, trading judge agreement for correct off-topic rejection and no double penalty; the choice is recorded here rather than hidden in the numbers.

**Bug 2: the UI showed a percentile as "Relevance".** `breakdown.relevance` is now the absolute cosine between the submission content and the fixed content (0.62 → 62%); novelty and recombination stay within-topic percentiles and are labelled "(percentile vs corpus)" in the UI. The within-topic relevance percentile appears only in the rationale text.

**Category removed.** Categories were dropped from the system (UI, API, scoring signal, judge prompt, datasets); blend weights were renormalized from 0.6/0.25/0.15 to knn/recombination only.

**Where the system falls short, and why.**

**C2 (PARTIAL).** Target: T1>T4>T3>T2 in ≥ 4/5 topics. Actual: 3/5 topics (planted-case pass-rate 60%). The order failed on four_day_week (T1 1.00, T4 0.12, T3 0.12, T2 0.00; broken: T4>T3); teen_social_media (T1 0.22, T4 0.08, T3 0.10, T2 0.00; broken: T4>T3). The characterized limitation: embedding cosine measures semantic distance, not idea-level novelty. A reworded near-duplicate (T3) moves away from its source in embedding space and is credited like a generic item (T4). Conversely, content that is topically adjacent to the corpus but conceptually new is under-credited (the lowest T1 above). An attempted mitigation, blending sentence-level net-new information into novelty (Δ Spearman -0.154, -0.017, -0.144, -0.003 across its variants), was rejected by the pre-registered keep/revert rule. It was never selected in any leave-one-topic-out fold (selected: AGG A info-weighted fields); its single-blend variants also scored lower against both held-out judge runs. It remains in the code, switched off (§3).

**C3 (PARTIAL).** Target: ≥ 80% of planted near-duplicates + generics in the bottom quartile. Actual: 66%. Part of the gap is structural: in leave-one-out, each near-duplicate's *original* is equally duplicated, so about 15 items per topic (5 copies, 5 originals, 5 generics) compete for 12.5 bottom-quartile slots. The rest is the same limitation as C2: rewrites that change wording but not the idea are not always close in embedding space. For reference, the Gemini judge's own scores place 92% of planted items in its bottom quartile.

## 5. Best practices

### Leave-one-topic-out selection (overfitting guard)

The configuration is never chosen by its in-sample score. For each topic, the best candidate (by mean per-topic Spearman) is selected on the other four topics and then evaluated on the held-out topic.

| held-out topic | selected on other 4 | in-sample Spearman | held-out Spearman | \|gap\| |
|---|---|---|---|---|
| ai_tutors | arctic-embed-m \| rankfusion \| asymmetric (deployed) | 0.470 | 0.502 | 0.031 |
| ev_green | arctic-embed-m \| linear \| asymmetric | 0.485 | 0.285 | 0.200 |
| four_day_week | arctic-embed-m \| rankfusion \| asymmetric (deployed) | 0.480 | 0.462 | 0.018 |
| remote_work | arctic-embed-m \| rankfusion \| asymmetric (deployed) | 0.478 | 0.469 | 0.010 |
| teen_social_media | arctic-embed-m \| rankfusion \| asymmetric (deployed) | 0.470 | 0.503 | 0.033 |

Mean in-sample 0.477, mean held-out 0.444, mean per-fold gap 0.058 (max 0.200). 2 distinct configuration(s) were selected across the 5 folds. When the same configuration wins every fold, the gap between the two *means* is zero by construction (here 0.033), which is why the per-fold gap is the reported generalization metric.

### Determinism vs judge variance

The full system was rebuilt from scratch 3 times (fresh model load, cleared memo, re-seeded) and scored 270 values each time: bit-identical = yes, max absolute difference 0.0e+00.

The judge was run 3 times per topic (run 0 in file order, later runs with a seeded shuffle of item order). Mean per-item variance 0.0080 (mean std 0.074, max variance 0.0748); 100% of items changed score between runs; mean run-to-run Spearman 0.843.

<sub>source: `results/experiments.json → determinism, judge_variance`</sub>

### The judge is a noisy, costly signal, not ground truth

The Gemini judge is used only to *measure* the system, never inside `system_score`. Its run-to-run agreement (above) suggests a practical ceiling on how closely any scorer can track it. Its verdicts are cached and never re-requested. The reference judge scores for corpus items come from a listwise leave-one-out protocol (one call per topic judges each item against the other N−1), which differs from the live one-submission protocol.

Judge models actually used (from the cache):

| model | topic/run |
|---|---|
| gemini-3-flash-preview | ai_tutors/run0, ai_tutors/run1, ev_green/run0, ev_green/run1, ev_green/run2, four_day_week/run0, four_day_week/run1, four_day_week/run2, remote_work/run0, remote_work/run2, teen_social_media/run0, teen_social_media/run1 |
| gemini-flash-latest | ai_tutors/run2, remote_work/run1, teen_social_media/run2 |

### Judge availability is explicit, never faked

`/api/score` returns `llm_source` ∈ {`live`, `cached`, `unavailable`}. A cached verdict is only ever the verdict for the exact same input (or, for a submission identical to a corpus item, that item's corpus reference score). On an API failure the rationale carries one short line (e.g. "LLM judge: unavailable (rate-limited)"), the raw error stays in the server log, and `llm_score` is 0.0 with the UI showing "n/a" rather than a number. All corpus judge scores are pre-cached by `experiments/precache_judge.py`.

### Reproducibility

Global seed `SEED = 1234` (`backend/scoring/config.py`); embeddings run locally (ONNX); judge verdicts are cached in `results/judge_cache.json`. Reproduce everything with:

## 7. Limitations & future work

- **Small corpus.** 50 items per topic, 5 topics, 4 held-out cases per topic. Percentiles move in steps of 0.02; one topic flipping changes pass-rate by 0.20.
- **Single-judge oracle.** Every reference score comes from one provider's models (gemini-3-flash-preview, gemini-flash-latest); the judge's own run-to-run Spearman is 0.843. Human labels or a multi-judge panel would give a firmer target.
- **Judge protocol mismatch.** Reference scores use the listwise protocol (all items in one prompt); the live API uses one submission per call. Position effects in the listwise prompt are only partially measured (runs 1–2 shuffle order).
- **Gate sensitivity.** Across the margin/target grid, Spearman ranged 0.470–0.490 and max T2 0.000–0.180. The gate temperature is now derived per topic from the on-topic distribution; with the same setting, max T2 was all-MiniLM-L6-v2 0.360, all-mpnet-base-v2 0.020, snowflake-arctic-embed-m 0.000 (rank fusion + asymmetric gate).
- **Relevance trade-off.** The judge's scores correlate with absolute relevance within a topic (mean Spearman 0.263): it marks weakly-relevant on-topic items down. The fixed gate deliberately does not, so it agrees less with the judge (§3, Bug fixes). A graded relevance term, separate from the gate, is the obvious next experiment if that agreement matters more than single-penalty semantics.
- **Judge prompt version.** Reference scores were produced with prompt version(s) legacy:6b1ca10fd0, legacy:8aba57b4c2, legacy:98fed1d5ba, legacy:b7c086df7e, legacy:def986b8bd. "legacy" means the judge prompt that still scored category (removed from the system since); the corpus will be re-judged with the category-free prompt when API quota allows (`run_experiments.py` without `--cache-only` fetches it).
- **Selection history.** The deployed configuration (embedding, k=1, rank fusion, temperature) was chosen in an earlier iteration using the same planted fixtures (planted-item AUC). Its C1–C3 results are therefore not fully out-of-sample; the LOTO judge-correlation result in §5 is the out-of-sample evidence.
- **Surfacing thresholds are in-sample.** The sentence model and the percentile cut-offs were chosen on the same fixtures reported above; paraphrased copies still read as partly new (planted-copy net-new 0.51 vs ordinary 0.77). Off-topic text reads as fully new at sentence level (T2 mean net-new 1.00); relevance is judged per submission, not per sentence. Sentence splitting is a punctuation regex.
- **Future work: productionization.** Aspect- or claim-level novelty (score the claims a submission makes, not whole-field embeddings), deployed as a two-tier ensemble: the cheap deterministic system audits every submission, and only uncertain or borderline cases escalate to the LLM judge.
- **Flag heuristics.** `flags.gaming` is a pattern check for grader-directed text plus the judge's verdict when available (not a trained detector); the dedup flag uses the p95 NN-similarity threshold, which sits above many close paraphrases.
